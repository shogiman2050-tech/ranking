## 更新手順

Python 3 の標準ライブラリだけで動きます。

```
python -m unittest test_build
python build_public.py
```

`build_report.txt`を確認し、生成された`dist/index.html`を公開します。エラーがある場合はビルドが失敗し、HTMLは更新されません。失敗時に古いHTMLを公開しないでください。

- `records.json`: 元の到達記録。ビルドでは書き換えません。
- `players.json`: 期間順、確認済み別名、未確認候補、記録単位の人物指定。
- `page.html`: 公開画面のテンプレート。
- `build_public.py`: 検査、人物の識別、HTML生成。
- `test_build.py`: 記録消失、誤統合、同率の回帰テスト。

## 人物の識別

「あ」もユーザー指示により同名で統合します。他の名前は文字数にかかわらず同名で集計し、確認済みの人物IDがある場合はそれを優先します。検索の全角半角・かな正規化は、人物の統合とは独立しています。

別名は`aliases`に登録し、同一人物と確認したものだけ`confirmed: true`にします。2026-10-29のユーザー指示で、指摘された11組を確認済みに変更しました。招待コードは接頭辞なしの表記と、元データにある接頭辞付きの大小文字違いも同じ人物へ統合します。確認済みの改名は引き続き統合します。

同名の別人を個別に指定するときは、生成HTML内の`recordId`をキーとして`record_identities`に人物IDを指定します。同一人物の記録には同じIDを使い、別人には別のIDを使います。IDは原記録の期間・クラス・名前・順位・CR・出典から生成するため、これらを修正したら指定も見直してください。

確認済みの別名表にない場合は既存のpersonKeyを優先し、なければ完全一致の名前で集計します。この場合も同名別人の可能性は残ります。同じ期間・クラスで同一人物が重複したらエラーにし、黙って記録を消しません。

## 検査

完全重複・同一期間クラス人物の重複・不正なCRや順位・未知の期間クラスはエラー。同率人数を考慮した順位欠落、順位重なり、CR逆転、同順位CR不一致、NFKC表記ゆれはレポートします。末尾の欠落は総人数情報がないため判定できません。

現在の欠落候補はクロニクル前半ビショップ67位相当、ネメシス20位相当です。いずれも同率グループの人数不足候補であり、その順位の人がいると断定するものではありません。

## 画面

同値は競争順位（1,1,3）。URLには期間・クラス・検索・条件・並べ替え・開いた人物を保存します。スマホ幅ではランキングをカードにし、詳細・平均表も縦表示にします。全ビヨ達成環境はPCでは最右列です。

期間は`players.json`の`seasons`に時系列順で追加します。選択肢とJSの期間順はこの設定から生成します。

公開HTMLは単体で開ける形式を維持しています。データ別ファイル化は未実装です。平均CRの横棒グラフ・期間別ヒートマップを表示します。広告試作とミニゲームは含めていません。


## 公開設定（2026-10-30）

`site.json` で公開URL・サイト名・説明・GA測定ID・報告フォームURLを設定します。`gaId`を空にすると解析タグと説明が外れ、`reportUrl`を設定するとフッターに報告リンクが出ます。フォーム自体は未作成です。

`python build_public.py` は元データ検査を通した後、`publish_assets.py`でHTML・共有画像・アイコン・robots.txt・sitemap.xml・404ページ・ホスティング用ヘッダーを生成します。最終更新日はビルド時の日本時間です。この段階の `dist` は静的版の中間生成物です。現行サイトの公開は下記「修正報告フォーム」の手順でWorkerをビルドしてください。共有カードがX・LINEに表示されるかは、各サービス側の取得・キャッシュにも依存します。

現在のchatgpt.siteは既存のSitesプロジェクトにWorkerとして公開します。静的ホスティングへの移転ではフォーム保存処理を別途用意する必要があります。このリポジトリではGitHubの自動公開設定は追加していません。`_headers`と`404.html`の適用方法はホスティング先に依存します。

## 総合スコア

1記録ごとに次の式で採点して合計します。

- 緩和モデル: `100 / rank**0.3`
- 逆数モデル: `100 / rank`
- 対数モデル: `(log10(101) - log10(rank)) * 50`

採点時のみ順位を最大100に丸めます。元記録の順位、最高順位、N位以内の判定は書き換えません。順位不明の記録はスコア計算から除外します。前回比は選択範囲の最終期間で加算されたスコアです。

`node test_scores.cjs` で全モデルの100位・101位・999位の同点、無効順位の除外、合計点、旧表記検索を検証します。

同じ期間・クラスの「あ」が複数ある場合、原記録・詳細・クラス平均にはすべて残し、個人の達成回数とスコアには最高CRの記録を1件採用します。この明示的な統合以外の人物重複は引き続きエラーです。

## 修正報告フォーム（2026-10-31追加）
- 公開フォーム: `/report`。報告は `/api/reports` に送信し、D1 `correction_reports` に非公開保存します。
- 閲覧者が報告を読むAPIはありません。所有者はSites設定のデータベース画面で確認できます。このチャットで「修正報告を確認して」でも取得できます。
- メール通知・ランキングの自動変更はありません。内容を確認して `records.json` / `players.json` を修正してください。
- フォーム本文は `report.html`、保存処理は `app/api/reports/route.ts`、DB定義は `db/schema.ts`。
- 公開用は従来の静的HTMLからWorkerへ移行しました。更新時は `python prepare_web.py` の後に `npm run build`。公開成果物は生成された `dist` です。
- DB定義変更時は `npm run db:generate` で新しいマイグレーションを作成します。既に適用したSQLは変更しないでください。
